# VC-session failures 2026-06-11 — end-to-end root cause

~1h live VC (Ben + Rew/Ralph/rjkelly), 21 music routes. Operator reported: double-queued music, random activation, spurious queues, random skips, music not playing, "put the music back on" ignored. Forensic correlation of `voice.log` + container stdout, then a 5-way code-level root-cause workflow with adversarial verification. **Models were healthy** (17 routes Groq gpt-oss-20b, 4 Gemini-3.1-flash-lite, 0 deep-fallback; latency = yt-dlp resolution, not the LLM).

## TWO shared defects (not one)

### Defect A — Deepgram utterance re-accumulation (→ double-QUEUE)
`_emit_utterance` fires on the LOCAL energy-VAD silence counter ([dual_pipeline.py:877-894](../../src/poob/voice/dual_pipeline.py#L877)) and `reset_transcript()` clears `stream.transcript` ([:998](../../src/poob/voice/dual_pipeline.py#L998)) **while Deepgram's utterance is still open** on the same persistent socket (interim_results + utterance_end_ms=1500, a different anchor than our 2000ms). Deepgram's later `is_final` segments re-append *from empty* ([:388-393](../../src/poob/voice/dual_pipeline.py#L388)), rebuilding the original phrase; a **log-silent OpenWakeWord re-fire** (`is_active = wake_hit` at [:856](../../src/poob/voice/dual_pipeline.py#L856), set before `speech_started` so the :835 "Wake word detected" log is skipped) re-addresses it. Both dedups miss: `_EMIT_DEDUP_WINDOW_S=8.0` (re-fires 14–29s apart) and brain `_DEDUP_WINDOW_S=20.0` (28s apart, or the LLM truncated the 2nd query so norms differ). Evidence: Funny Friends 23:30:11+25 (identical → 50-min Friends TV compilation); Take-a-Drive 00:07:09+38 (mutated to "…Rex orange"). Aggravator: `_emit_utterance` is reachable from two unsynchronized threads (recording + 100ms stale-checker) with no lock.

### Defect B — passive context leaks into the escalation heuristic (→ double-SKIP)
`_groq_with_tools` computes `looks_tool_worthy` over `user_msg` = the FULL `_build_messages`-rewrapped prompt **including the `[Recent conversation you've been listening to:…]` prefix** ([poob.py:2097-2128](../../src/poob/brain/poob.py#L2097), context built at [:1285-1292](../../src/poob/brain/poob.py#L1285)). A stale "skip" in that window sets `looks_tool_worthy=True`, the soft-escalation refuses Groq's correct no-tool answer and escalates to Gemini, which **hallucinates `action=skip`**. The play-query hallucination guard only runs for `action=='play'`, so skip/stop bypass it. Evidence: 00:11:49 phantom skip (no addressed event) → queue empty → music stopped.

## Ordered fix plan (leverage × risk)

1. **double_skip — Fix 1 (ship first, lowest risk):** narrow `user_msg` to the CURRENT TURN via the existing `_split_context`/`_CONTEXT_RE` ([poob.py:512-554](../../src/poob/brain/poob.py#L512)) before BOTH the deal `tool_signals` and music `control_signals` checks. Do NOT touch the soft-escalation valve (CLAUDE.md soft-fail rule) — only clean stale tokens from its input. **Fix 2 (defense-in-depth):** `_is_duplicate_control(guild_id,user_id,action)` for one-shot destructive actions (skip/previous/stop/pause) with a SHORT ~3–5s window, recorded only when the control actually fired (mirror `_clear_play_on_failure`). Brain layer, NOT MusicCog (button clicks must stay un-deduped).
2. **double_queue — Commit 1 (airtight):** SEAL-ON-EMIT — `_UserStream.utterance_seq`/`emitted_seq`; `_listen_loop` bumps seq on speech_final/UtteranceEnd; `get_transcript` returns "" for content `seq<=emitted_seq` — **sealing BOTH `transcript` AND `latest_interim`** (the interim-fallback at :481-483 is the leak path). Per-user `threading.Lock` on read-emit-reset; the GIL-atomic seq compare (not the lock) handles the listener-vs-emit interleave. Fix the silent re-arm observability (log the wake on the speech-start path). Zombie-counter guard: a sealed re-append must NOT trip `force_reconnect`. *Discriminator:* a genuine re-request is a NEW utterance (new seq) → still emits.
3. **restore_last_song — Fix A+B (ship together):** **(B)** the loop advance sets `queue.current=None` directly ([player.py:1015/1018](../../src/poob/music/player.py#L1015)) so `get_next` never appends to `_history` → history is structurally ALWAYS empty in OFF mode → `previous()` fails for everyone. Replace with a **loop-mode-aware** `queue.archive_current()` (OFF-mode archives; LOOP_QUEUE archiving stays owned by `get_next` or its recycle silently breaks). Leave download-abandon `current=None` as-is (never-played tracks must not archive). **(A)** add resume/restore phrase mapping to `_MUSIC_ROUTING_RULES` → one `GuildMusicPlayer.restore_last()` (paused→resume; history→previous; else `_last_played_track`→re-enqueue reusing the done()-guarded task start; else `[SILENT]`). Guard restore-after-explicit-stop.
4. **double_queue — Commit 2 (separate, touches zombie path):** prefer the Deepgram-final emit boundary (defer until speech_final via the existing `_deferred_emit`). Fixes the query truncation. Needs its own decision note + short-command latency test.
5. **search_quality (after replay-set validation):** relative-outlier candidate selection in `AsyncYTDL.search` — cheap FLAT `ytsearch5` (extract_flat, not full — full would 5× the queue_many/Spotify batch loops), median, demote gross outliers (>~4× median AND >`music_search_max_song_seconds`~1800s floor); keep top if all long. duration=None skipped from median. **Logging-only for one session first** — "this alone prevents the 50-min queue" is untested.
6. **false_activation (LAST, gated on data):** `_deferred_emit` calls `_do_emit(is_addressed=True)` HARDCODED, bypassing the dual-gate ([:1010](../../src/poob/voice/dual_pipeline.py#L1010)). Naive tighten REGRESSES [[wake-address-hey-dropout]] (5/53 real addresses rescued ONLY via the deferred hardcoded-True). Required: a THIRD signal — keep addressed when `text_match OR (audio_match AND command-verb present)`. **Measure the deferred-path real-vs-spurious ratio before shipping** (add `deferred=True` to `_do_emit` logging); if indefensible, surface a research prompt per CLAUDE.md.
